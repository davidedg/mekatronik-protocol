# `13` - Read the macro data

| bmRequestType | bRequest | wValue | wIndex | wLength |
|---|---|---|---|---|
| `c0` | `13` | `0000` | profile, `0001` to `0003` | at most `1000`, see below |

Reply: the [macro data](../../formats/macro-data.md) of the profile, from its start. The vendor software does not read it.

```
27 bytes of data, asked with wLength 512:
< c0 13 0000 0001 0200
  84 04 01 87 00 03 84 04 00 87 00 26 84 05 01 87 00 01 84 05 00 86 00 01 87 00 01

5724 bytes of data (0x165c), asked with wLength 4096:
< c0 13 0000 0002 1000
  <bytes 0 to 4095 of the data, 0.5 s after the setup>
```

- **The keyboard answers min(wLength, total length)**: asked for 512 bytes, profile 1 answered its 27 bytes; asked for 4096, a profile with 5724 bytes answered its first 4096 bytes, identical to what was written.
- **Only the first 4096 bytes can be read.** Data beyond that is not readable: the tool that writes it has to keep its own copy.
- The reply is slow, like the writes: 485 to 544 ms for 4096 bytes.

**Danger.** These requests left the keyboard stalling every control request and no key working, until it was unplugged (power cycle):

| Request | Profile | Result |
|---|---|---|
| wLength 512 | never written (index all `ff`) | profile 3: no answer (3 s timeout), then hung |
| wValue `1000`, wLength `065c` (an offset, as [`12`](../12/12.md) writes) | 5724 bytes of data | no answer (10 s), then hung |
| wLength 4097 | 5724 bytes of data | no answer (10 s), then hung |

The profiles were intact after the power cycle. On a never-written profile, profile 2 instead answered 512 bytes of old memory content.

Rules: read only a profile whose [macro index](../11/11.md) is valid and has a total length above 0; wValue `0000`; wLength at most min(total length, 4096).

Host side: Linux refuses synchronous control transfers above 4096 bytes (libusb and `USBDEVFS_CONTROL` give EINVAL, nothing reaches the bus), so the limit above is the only one a Linux host meets in practice. Seen under VMware Workstation (Windows 11 host): control transfers above 4096 bytes failed with a protocol error before reaching the keyboard, which did not hang.
