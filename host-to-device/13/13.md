# `13` - Read the macro data

| bmRequestType | bRequest | wValue | wIndex | wLength |
|---|---|---|---|---|
| `c0` | `13` | `0000` | profile, `0001` to `0003` | the total length from the macro index |

Reply: the [macro data](../../formats/macro-data.md) of the profile. Asked with wLength 512, profile 1 answered exactly its 27 bytes of data. The vendor software does not read it.

**Danger.** Read it only for a profile whose [macro index](../11/11.md) is valid and has a total length above 0, and ask for that length. On a profile that was never written (index all `ff`):

- profile 2 answered 512 bytes of old memory content;
- profile 3 did not answer (3 s timeout), and from then on **the keyboard stalled every control request and no key worked**: disconnecting and reconnecting the USB device in the virtual machine did not help, only unplugging the keyboard (power cycle). The profiles were intact afterwards.

Only data of up to 27 bytes was read back; reading longer data has not been tried.
