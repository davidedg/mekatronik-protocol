# `02` - Work mode

| bmRequestType | bRequest | wValue | wIndex | wLength |
|---|---|---|---|---|
| `40` | `02` | mode | `0000` | `0000` |

| Mode | Meaning |
|---|---|
| `0001` | **Normal mode**: the keyboard types its default layout on the boot keyboard interface ([`81`](../../device-to-host/81/81.md)); the [key matrix](../../formats/matrix.md) of the profile is not used. T1 to T12 run their macros, Instant Shift works. |
| `0003` | **Game mode**: the key matrix of the profile is used (remaps, T13 to T20), keys are typed on the NKRO interface ([`83`](../../device-to-host/83/83.md)), and **the Windows key sends nothing** (left one tried). |

Seen: the Windows software sends `0001` or `0003` when it starts (from its saved setting) and when its Normal Mode or Game Mode page is clicked; the mode changes at once. Only these two values were seen, and no other value was tried.

- The keyboard sends no notification when the host changes the mode; the Normal/Game key on the keyboard does ([`81`](../../device-to-host/81/81.md): `f8` Game, `f9` Normal).
- **The mode cannot be read back**: no request seen returns it ([`05`](../05/05.md) answers the same in both modes). The vendor software never asks; it imposes its saved mode at start and then follows the notifications. A host that needs the mode must set it.
- Seen: in Game mode a press of the left Windows key produced no report at all; in Normal mode it sent `08` on the boot report.
- The keyboard has no light showing the mode or the profile; the vendor software shows them on screen when it gets the [notifications](../../device-to-host/81/81.md).
