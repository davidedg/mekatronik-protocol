# `81` - Boot keyboard report and notifications

Interface 0, interrupt IN endpoint `0x81`, 8 bytes: the standard boot keyboard report (modifiers, reserved byte, six key codes) of [the descriptor](../../lsusb/060b/5253/0135).

```
08 00 00 00 00 00 00 00   left Windows key pressed
00 00 45 00 00 00 00 00   F12
```

In **Normal mode** the keyboard types on this report, keys and macros alike; in **Game mode** it types on the NKRO report [`83`](../83/83.md) and uses this one only for notifications ([`02`](../../host-to-device/02/02.md)).

After the host selects a profile ([`14`](../../host-to-device/14/14.md)) the keyboard sends an all-zero report here and on [`83`](../83/83.md).

## Notifications

The keyboard reports its own events as a fake key code in byte 2, followed by an all-zero report:

```
00 00 f3 00 00 00 00 00
00 00 00 00 00 00 00 00
```

Byte 0 keeps the modifiers held at the time: an Instant Shift with left Ctrl in Normal mode gives `01 00 f3 00 00 00 00 00`, then `01 00 00 ...` while Ctrl is held ([`1a`](../../host-to-device/1a/1a.md)).

| Byte 2 | Event |
|---|---|
| `f1`, `f2`, `f3` | profile 1, 2, 3 is now active: a profile key, or an Instant Shift modifier pressed (`f2`/`f3`) and released (back to the profile, e.g. `f1`) |
| `f8` | Game mode on (Normal/Game key) |
| `f9` | Normal mode on (Normal/Game key) |
| `fa` to `fe` | backlight level 0 to 4 (backlight key: `fa` `fb` `fc` `fd` `fe` `fa` ...) |

Changes made by the host ([`14`](../../host-to-device/14/14.md), [`02`](../../host-to-device/02/02.md)) are not notified.

On Windows the vendor software shows these events on screen and saves the new profile and mode in its settings file. The keyboard itself has no light for the profile or the mode: these notifications are the only way to know them, besides [`15`](../../host-to-device/15/15.md) for the profile. (Once the vendor software stopped showing them until it was restarted, while the keyboard kept sending them.)

Without vendor software the codes reach the operating system as ordinary key codes. **On Linux**, `hid-input` maps keyboard usages `e8` to `fb` to media keys *(inferred from its table, not tried)*: `f1` KEY_BACK, `f2` KEY_FORWARD, `f3` KEY_STOP, `f8` KEY_SLEEP, `f9` KEY_COFFEE (screen lock), `fa` KEY_REFRESH, `fb` KEY_CALC; `fc` to `fe` have no mapping. A host program should catch them (hidraw) and neutralise them (hwdb or udev), above all `f8`, which a desktop may take as "suspend".
